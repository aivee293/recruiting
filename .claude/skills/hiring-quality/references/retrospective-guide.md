# Retrospective Facilitation Guide

Step-by-step guide for running search retrospectives after every closed role (filled or cancelled). The retro closes the learning loop — without it, the same mistakes repeat across searches.

---

## 1. Pre-Retro Preparation

**Facilitator:** Usually the recruiter who owned the search. If the recruiter is too close to the process, a recruiting manager or peer can facilitate instead.

**What to gather beforehand:**

- [ ] Pipeline data: candidates at each stage, conversion rates, drop-off points
- [ ] Timeline: actual dates for each milestone vs original target dates
- [ ] Source data: which channels produced candidates, which produced hires/finalists
- [ ] Scorecard summaries: interviewer ratings, common themes in feedback
- [ ] Candidate experience survey results (if available)
- [ ] HM experience survey results (if available)
- [ ] The original persona/JD and the profile of the person actually hired (or why it was cancelled)
- [ ] Brief.md pipeline table and search log

**How to prepare the agenda:**

- Pre-fill the timeline review section with actual data so time isn't wasted pulling numbers in the meeting
- Identify 2-3 discussion topics you think are worth exploring (but let the group surface their own too)
- Send the agenda and data summary to attendees 24 hours before so they come prepared

**How to set up the room/call:**

- 30-45 minutes is the right length — shorter and you skip depth, longer and energy drops
- If remote, have a shared document open for real-time notes
- If in person, whiteboard with the agenda sections pre-drawn

---

## 2. Running the Retro

### Opening (2 minutes)

Set the tone. The facilitator should say something like:

> "The goal is to learn, not to assign blame. Everything discussed here is about improving the process for next time. There are no wrong answers — if something frustrated you, it's worth mentioning."

Ground rules:
- Focus on the process, not individuals
- Specific examples are more useful than general impressions
- It's okay to disagree — capture both perspectives
- Action items need an owner and a date or they won't happen

### Timeline Review (5 minutes)

Walk through the actual timeline vs the target:

| Milestone | Target Date | Actual Date | Delta | Notes |
|-----------|------------|-------------|-------|-------|
| Role opened | | | | |
| Intake complete | | | | |
| First candidates presented | | | | |
| First interview | | | | |
| Final round complete | | | | |
| Offer extended | | | | |
| Offer accepted / role closed | | | | |

**Facilitator prompts:**
- "Where did we lose the most time?"
- "Was any delay avoidable? What would have prevented it?"
- "Did the timeline feel right to the hiring manager?"

### What Worked (10 minutes)

**Facilitator prompts:**
- "Which sourcing channel produced the strongest candidates?"
- "Was there an interview stage that was especially good at identifying the right people?"
- "Who was particularly helpful in this process — interviewers, coordinators, anyone?"
- "What would you definitely do again?"

Capture specific, repeatable wins — not just "it went well" but "the technical assessment caught a critical skill gap that phone screens missed."

### What Didn't Work (10 minutes)

**Facilitator prompts:**
- "Where did we waste the most effort?"
- "Which channels produced low-quality candidates?"
- "Was there a point where the process felt stuck or broken?"
- "What feedback did candidates give us about their experience?"
- "If you could redo one part of this search, what would it be?"

**Handling difficult dynamics:**

- **Dominating voice:** "That's a good point — let me hear from [quiet person] on this too."
- **Quiet participant:** "You were involved in [specific stage] — what was your experience there?"
- **Blame dynamics:** "Let's focus on the process rather than individuals. What about the system made that outcome likely?"
- **Defensive hiring manager:** "I hear you — let's capture that perspective. What would have made the candidates more aligned?"
- **Tangent:** "Interesting — let me note that for later. Coming back to [current topic]..."

### Calibration Accuracy (5 minutes)

Compare the original persona to the person hired (or the finalists, if cancelled):

**Facilitator prompts:**
- "How closely did the hired candidate match our original persona?"
- "Did we recalibrate during the search? When and why?"
- "Were we looking for the right things from the start, or did we discover what we actually needed?"
- "Were there must-haves that turned out not to matter, or nice-to-haves that turned out to be critical?"

This section is especially valuable for improving intake quality on future roles.

### Source Effectiveness (5 minutes)

Review channel-level data:

| Source | Candidates Sourced | Screened | Interviewed | Finalist | Hired |
|--------|-------------------|----------|-------------|----------|-------|
| LinkedIn outbound | | | | | |
| Referrals | | | | | |
| Inbound applications | | | | | |
| Agency | | | | | |
| Other | | | | | |

**Facilitator prompts:**
- "Which channel had the best conversion rate, not just the most volume?"
- "Would you invest more or less in each channel next time?"
- "Were there channels we didn't try that we should have?"

### Process Friction (5 minutes)

**Facilitator prompts:**
- "Were there scheduling delays? What caused them?"
- "Did any tools or systems create friction?"
- "Was interviewer availability a problem?"
- "Did the approval process slow things down?"
- "Were there handoff points where information got lost?"

### Lessons & Action Items (5 minutes)

Narrow down to 3-5 specific, actionable takeaways. Each needs an owner and a timeline.

**Facilitator prompt:**
- "If we opened this exact role again tomorrow, what would we do differently?"

## 3. Example Retro Output

```markdown
# Search Retrospective: Senior Backend Engineer

**Role:** Senior Backend Engineer — Platform Team
**Recruiter:** Alex Chen
**Hiring Manager:** Jordan Park
**Date closed:** 2026-01-28 (filled)
**Retro date:** 2026-02-04
**Attendees:** Alex Chen (Recruiter), Jordan Park (HM), Sam Lee (Lead Interviewer)

## Timeline

| Milestone | Target | Actual | Delta |
|-----------|--------|--------|-------|
| Role opened | Dec 2 | Dec 2 | — |
| Intake complete | Dec 4 | Dec 5 | +1 day |
| First candidates presented | Dec 11 | Dec 16 | +5 days |
| First interview | Dec 16 | Dec 20 | +4 days |
| Final round complete | Jan 6 | Jan 15 | +9 days |
| Offer extended | Jan 10 | Jan 20 | +10 days |
| Offer accepted | Jan 17 | Jan 28 | +11 days |

**Total time-to-fill:** 57 days (target: 45 days, +12 days over)

**Where time was lost:** Holiday scheduling (Dec 23 - Jan 2 lost ~8 business days),
one finalist withdrew during final round forcing a re-pipeline.

## What Worked

- **Referral channel produced the hire.** Jordan's referral from a former colleague
  was the strongest candidate from day one. Lesson: always mine the HM's network early.
- **Technical assessment was strong.** The take-home + live review format correctly
  identified the top 2 candidates. Both finalists scored highest on the assessment.
- **Quick intake.** Jordan came prepared with clear requirements and examples of
  successful profiles. Intake took 30 minutes instead of the usual hour.

## What Didn't Work

- **Initial persona was too narrow.** Required Rust experience eliminated 60% of
  otherwise-qualified candidates. After 2 weeks, relaxed to "Rust or Go with
  willingness to learn Rust." Should have started there.
- **LinkedIn outbound had low conversion.** 47 InMails sent, 8 responses (17%),
  2 interested (4%). The messaging didn't differentiate the role enough from
  similar Platform Engineer postings.
- **Scheduling delays in final round.** Two panel interviewers were unavailable
  for 10+ days. Need backup interviewers trained and ready.
- **Lost a finalist to slow process.** Candidate B accepted another offer while
  waiting for our final round to be scheduled. The 9-day delay between first
  interview and final round was the root cause.

## Source Effectiveness

| Source | Sourced | Screened | Interviewed | Finalist | Hired |
|--------|---------|----------|-------------|----------|-------|
| LinkedIn outbound | 47 | 8 | 3 | 1 | 0 |
| Referrals | 4 | 3 | 2 | 1 | 1 |
| Inbound | 23 | 5 | 1 | 0 | 0 |
| GitHub/community | 12 | 3 | 1 | 0 | 0 |

**Takeaway:** Referrals had 25% hire rate vs LinkedIn's 0%. Next similar role:
spend the first week mining referrals before scaling outbound.

## Calibration Notes

Original persona required 5+ years backend + Rust production experience.
Hired candidate had 7 years backend, Go expert, 6 months Rust side projects.
The Rust requirement was a "nice-to-have" dressed up as a "must-have."
Jordan acknowledged this in week 2 — next time, push harder on must-have
vs nice-to-have during intake.

## Action Items

| # | Action Item | Owner | Due | Status |
|---|-------------|-------|-----|--------|
| 1 | Train 2 backup interviewers for platform team panels | Jordan | Feb 14 | Open |
| 2 | Rewrite platform team outreach to emphasize Rust learning opportunity, not Rust requirement | Alex | Feb 7 | Open |
| 3 | Add "mine HM network" as step 1 in sourcing plan template | Alex | Feb 7 | Open |
| 4 | Set SLA: max 5 business days between interview rounds | Alex + Jordan | Feb 14 | Open |
| 5 | Revisit must-have vs nice-to-have framework during intake — push back on requirements that shrink pool >50% | Alex | Ongoing | Open |
```

## 4. Cross-Role Pattern Analysis

After running retros for 5+ closed searches, look across them for systemic patterns. This is where individual learnings become organizational improvements.

**How to analyze:**

1. **Collect all retro action items in one place.** A simple spreadsheet or table works. Tag each item by category (sourcing, process, calibration, scheduling, tools).

2. **Look for repeating themes.** If "scheduling delays" appears in 4 of 5 retros, it's systemic — fix the system, not the individual search.

3. **Compare source effectiveness across roles.** Build a table:

| Source | Roles Where It Produced Hires | Roles Where It Produced Nothing | Avg Conversion Rate |
|--------|------------------------------|--------------------------------|-------------------|
| Referrals | | | |
| LinkedIn outbound | | | |
| Inbound | | | |
| Agencies | | | |
| GitHub/community | | | |

4. **Identify stage drop-off patterns.** If candidates consistently drop off between "Interested" and "Screening," there's a scheduling or follow-up gap. If they drop off between "Interview" and "Offer," there's a closing or comp issue.

5. **Track calibration accuracy.** How often does the hired candidate match the original persona? If less than 50%, intake quality needs systemic improvement.

**Questions to ask across retros:**

- What patterns repeat?
- Which channels consistently produce vs don't?
- Where do candidates consistently drop off?
- What process improvements keep getting requested but never implemented?
- Are the same interviewers repeatedly flagged as bottlenecks?
- Do certain role families have systematically longer time-to-fill? Why?

**Cadence:** Run the cross-role analysis quarterly or after every 5 closed searches, whichever comes first. Share findings with the recruiting team and hiring leadership.

## 5. Action Item Template

Use this format for tracking retro action items. Each item must have an owner and a due date or it will not happen.

| # | Action Item | Owner | Due | Status |
|---|-------------|-------|-----|--------|
| 1 | | | | Open |
| 2 | | | | Open |
| 3 | | | | Open |

**Status values:** Open → In Progress → Done → Won't Do (with reason)

**Rules for good action items:**

- Specific and measurable — "improve sourcing" is not an action item, "rewrite LinkedIn outreach template for engineering roles" is
- One owner — shared ownership means no ownership
- Time-bound — "by next retro" or a specific date
- Review in the next retro — if action items aren't reviewed, the retro loop is broken
- Limit to 3-5 items per retro — more than that and nothing gets done
