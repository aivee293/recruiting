# Onboarding Checklists

Pre-boarding and onboarding checklist templates by role family. These cover the recruiter's responsibility in the handoff — everything from offer acceptance through the first 30 days.

---

## 1. Engineering Onboarding Checklist

### Equipment & Hardware

- [ ] Laptop ordered (spec: confirm with engineering manager — typically 16"+ MacBook Pro or Linux-compatible alternative)
- [ ] External monitors (2x recommended for engineering)
- [ ] Peripherals: keyboard, mouse, headset, webcam (if remote or hybrid)
- [ ] Standing desk / ergonomic setup (if in-office)
- [ ] Ship date confirmed (arrive 2+ days before start for setup)

### System Access

- [ ] Email account created
- [ ] Slack / Teams workspace added
- [ ] GitHub organization access (correct teams and repos)
- [ ] CI/CD platform access (GitHub Actions, Jenkins, CircleCI, etc.)
- [ ] Cloud provider console (AWS, GCP, Azure — role-appropriate permissions)
- [ ] Monitoring and observability tools (Datadog, PagerDuty, Grafana, etc.)
- [ ] Internal tools (wiki, documentation platform, design system)
- [ ] VPN / network access configured
- [ ] Password manager / SSO enrollment
- [ ] JIRA / Linear / project management tool access

### Development Environment

- [ ] Dev environment setup guide shared (or automated setup script)
- [ ] Local development prerequisites documented
- [ ] Test/staging environment access
- [ ] API keys and credentials (via secrets manager, not plaintext)

### Knowledge Transfer & Ramp

- [ ] Architecture overview document or diagram shared
- [ ] Code walkthrough scheduled with tech lead (first week)
- [ ] Key repositories identified with README links
- [ ] On-call rotation explained (when they'll join, how it works)
- [ ] Team norms document (PR review expectations, coding standards, meeting cadence)

### People & Support

- [ ] Buddy assigned (an engineer on the team, not the manager — ideally someone who joined in the last 6-12 months)
- [ ] Buddy briefed on responsibilities and meeting cadence
- [ ] 1:1 with engineering manager scheduled (Day 1)
- [ ] Team lunch or virtual coffee scheduled (Week 1)
- [ ] Skip-level intro scheduled (first 2 weeks)

### First Work

- [ ] First ticket or starter project identified (should be completable in first 1-2 weeks, non-critical path)
- [ ] PR review expectations set (they should be reviewing PRs by week 2)
- [ ] 30/60/90 day goals discussed and documented

## 2. GTM (Sales/Marketing/CS) Onboarding Checklist

### Equipment & Hardware

- [ ] Laptop ordered (standard spec per IT policy)
- [ ] External monitor (1x standard for GTM)
- [ ] Headset (quality matters for Sales — invest in a good one)
- [ ] Webcam (if remote or hybrid)
- [ ] Ship date confirmed

### System Access

- [ ] Email account created
- [ ] Slack / Teams workspace added
- [ ] CRM access (Salesforce, HubSpot, Pipedrive — role-appropriate permissions)
- [ ] Marketing automation platform (HubSpot, Marketo, Pardot — if marketing)
- [ ] CS platform (Intercom, Zendesk, Gainsight — if CS)
- [ ] Sales engagement platform (Outreach, Salesloft, Apollo — if sales)
- [ ] Revenue intelligence tools (Gong, Chorus — if applicable)
- [ ] Business intelligence / reporting (Looker, Tableau, internal dashboards)
- [ ] Content management / DAM (Google Drive, Notion, Confluence)
- [ ] Password manager / SSO enrollment

### Knowledge Transfer & Ramp

- [ ] Product demo environment access and training scheduled
- [ ] Sales playbook / marketing playbook shared
- [ ] ICP (Ideal Customer Profile) and buyer persona documents shared
- [ ] Competitive landscape overview shared
- [ ] Pricing and packaging documentation shared
- [ ] Case studies and customer stories shared
- [ ] Shadowing schedule created (minimum 5 calls/meetings in first 2 weeks)

### Territory / Account Setup (Sales & CS)

- [ ] Territory or account list assigned
- [ ] CRM data cleaned and accounts transferred
- [ ] Existing pipeline reviewed with manager
- [ ] Warm introductions to key accounts (if applicable)
- [ ] Handoff notes from previous rep (if backfill)

### People & Support

- [ ] Buddy assigned (a peer who is performing well, not the manager)
- [ ] Buddy briefed on responsibilities
- [ ] 1:1 with manager scheduled (Day 1)
- [ ] Cross-functional intros scheduled: Product, Engineering, Finance (first 2 weeks)
- [ ] Team meeting cadence shared (standups, pipeline reviews, QBRs)

### First Targets

- [ ] Quota ramp plan documented (typically 0% Month 1, 50% Month 2, 100% Month 3 — or per company policy)
- [ ] First outreach or campaign targets identified
- [ ] First customer call or meeting scheduled (Week 2)
- [ ] 30/60/90 day goals discussed and documented

- [ ] Travel preferences documented (if travel expected)
- [ ] Expense policy and corporate card setup

### Knowledge Transfer & Strategic Context

- [ ] Budget and headcount plan for their function

- [ ] Competitive landscape briefing

- [ ] Leadership team 1:1 schedule (all C-suite/VP+ in first 2 weeks)

## 4. Universal Pre-Boarding Timeline

Applies to all role families. Adjust specific items per the role-specific checklists above.

| Timing | Action | Owner | Notes |
|--------|--------|-------|-------|
| **Offer + 1 day** | Welcome email from hiring manager | Hiring Manager | Personal, warm, expresses excitement. Not a form letter. |
| **Offer + 3 days** | Equipment and access request submitted to IT | Recruiter | Include start date, role, manager, and specific access needs per checklist above. |
| **Offer + 5 days** | Buddy assigned and briefed | Hiring Manager | Share the buddy guide (below). Buddy should reach out before Day 1. |
| **Offer + 1 week** | Background check / references completed (if not done pre-offer) | Recruiter/HR | Don't let this linger — delays create anxiety for the new hire. |
| **Day -7** | Pre-boarding email with logistics | HR/Recruiter | What to bring, where to go (or ship tracking for remote), dress code, parking, first-day schedule, who to ask for. |
| **Day -5** | Buddy reaches out | Buddy | Informal intro — "Looking forward to working together, here's what to expect on Day 1." |
| **Day -2** | Final confirmation: everything ready | Recruiter | Check: equipment arrived/set up, access provisioned, first-week calendar populated, buddy confirmed. |
| **Day 1** | Orientation, team intro, manager 1:1, buddy lunch | HM + HR + Buddy | Morning: logistics and setup. Afternoon: team and context. |
| **Day 2-5** | Ramp activities per role-specific checklist | HM + Buddy | Shadowing, code walkthroughs, playbook reviews, system training. |
| **Day 7** | Recruiter check-in | Recruiter | "How's the first week going? Anything falling through the cracks?" |
| **Day 14** | Manager check-in on ramp progress | Hiring Manager | Confirm 30/60/90 goals are clear and ramp is on track. |
| **Day 30** | QoH survey — 30-day check-in | Recruiter | Send to HM. See survey-templates.md. |

## 5. Welcome Communication Templates

### HM Welcome Email (send Day +1 after offer acceptance)

```
Subject: Welcome to the team, [First Name]!

Hi [First Name],

I'm thrilled you've accepted the offer. The whole team is looking forward
to having you join us.

A few things before your first day:

- [Buddy Name] will be your onboarding buddy — they'll reach out in the
  next few days to introduce themselves
- Your first day is [Date]. [Logistics: where to go / what time / remote
  setup instructions]
- [Recruiter Name] will send you a pre-boarding email with all the
  practical details closer to your start date

In the meantime, if you have any questions at all, don't hesitate to
reach out to me directly.

Looking forward to [specific thing — e.g., "working on the platform
migration together" / "tackling Q2 pipeline goals" / "building out the
team"],

[HM Name]
```

### Team Introduction Email (send Day 1, from HM to the team)

```
Subject: Welcome [First Name] to [Team Name]!

Team,

[First Name] [Last Name] is joining us today as [Title]. They're coming
from [Brief background — previous company, relevant experience].

[1-2 sentences about what they'll be working on and why we're excited.]

[First Name]'s buddy is [Buddy Name]. Please make them feel welcome —
drop by to say hello, invite them to lunch, and be generous with context
when they have questions.

[First Name] — welcome! The team is great and you'll fit right in.

[HM Name]
```

### Buddy Introduction Email (send Day -5, from Buddy to New Hire)

```
Subject: Hey [First Name] — your onboarding buddy here

Hi [First Name],

I'm [Buddy Name], and I'll be your onboarding buddy when you start on
[Date]. My role is [brief description] — I joined the team [X months ago]
so I still remember what it's like being new here.

I'm here for anything you need: questions about the team, how things
work, where to find stuff, or just someone to grab coffee with. No
question is too small.

A couple of things that would have helped me on Day 1:
- [Practical tip — e.g., "The wifi password is on the wall by the kitchen"
  or "Slack is where everything happens — check the #team-[name] channel
  first"]
- [Cultural tip — e.g., "Standup is at 9:30 but people are flexible about
  cameras" or "Lunch crew usually goes out Wednesdays"]

Looking forward to meeting you!

[Buddy Name]
```

### Pre-Boarding Logistics Email (send Day -7, from HR/Recruiter)

```
Subject: Everything you need for Day 1 at [Company]

Hi [First Name],

Your first day is [Date]! Here's what you need to know:

**Getting started:**
- [If in-office] Arrive at [Address] by [Time]. Ask for [Contact Name]
  at reception.
- [If remote] Your equipment [has been shipped — tracking: XXX / will be
  ready for pickup at...]. Setup instructions are included in the box.
- [If hybrid] Your first [X days/weeks] will be [in-office/remote].
  Office address: [Address].

**What to bring:**
- Government-issued ID (for I-9 verification)
- [Any other documents]
- A notebook — there's a lot to absorb on Day 1

**Your first day schedule:**
- [Time]: Welcome and orientation with [HR Contact]
- [Time]: Team introduction with [HM Name]
- [Time]: Buddy lunch with [Buddy Name]
- [Time]: System setup and access walkthrough

**Key contacts:**
- Your manager: [HM Name] ([email])
- Your buddy: [Buddy Name] ([email])
- HR/People: [HR Contact] ([email])
- IT support: [IT Contact or helpdesk email]

If anything comes up before your start date, reach out to me at [email]
or [phone].

See you on [Date]!

[Recruiter/HR Name]
```

## 6. Buddy Program Setup

### What Makes a Good Buddy

A buddy is NOT a mentor, manager, or trainer. They're a peer navigator — someone who helps the new hire figure out how things actually work (vs how the handbook says they work).

**Ideal buddy profile:**

- Peer-level (not the manager, not too junior)
- On the same team or closely adjacent
- Joined within the last 6-12 months (fresh memory of being new, but has enough context to be helpful)
- Good communicator — approachable, patient, responsive
- Positive about the team and company (not a venter)
- Volunteered or is willing — forced buddies are bad buddies

**Who should NOT be a buddy:**

- The new hire's direct manager (power dynamic changes the relationship)
- Someone overwhelmed with their own work (they'll deprioritize buddy duties)
- Someone brand new themselves (blind leading the blind)
- Someone leaving the team soon

### Buddy Responsibilities Checklist

- [ ] Reach out before Day 1 to introduce yourself (see email template above)
- [ ] Be available on Day 1 for questions and lunch/coffee
- [ ] Walk them through team norms, tools, and unwritten rules
- [ ] Introduce them to key people they'll work with
- [ ] Check in daily during Week 1 (brief, casual — "How's it going? Need anything?")
- [ ] Check in weekly for the rest of the first 90 days
- [ ] Be the "no stupid questions" person — create psychological safety
- [ ] Flag any concerns to the manager early (if the new hire seems lost, unhappy, or struggling)
- [ ] Help them navigate their first PR / first deal / first project deliverable

### Suggested Buddy Meeting Cadence

| Period | Frequency | Duration | Focus |
|--------|-----------|----------|-------|
| Week 1 | Daily | 15-30 min | Survival: tools, norms, who to ask for what, lunch |
| Weeks 2-4 | 2-3x per week | 15-20 min | Getting productive: workflow, codebase/systems, team dynamics |
| Weeks 5-8 | Weekly | 15-20 min | Building confidence: independence, cross-team navigation, feedback |
| Weeks 9-12 | Weekly or biweekly | 15 min | Sustained support: check-in, address any lingering gaps |
| After 90 days | As needed | — | Relationship transitions to normal peer relationship |

**Buddy time commitment:** ~3-5 hours in Week 1, ~1-2 hours/week for months 2-3, tapering off. Set this expectation with the buddy upfront so they can plan their workload.

### Briefing the Buddy

When assigning a buddy, the manager should share:

- The new hire's name, title, start date, and background (keep it brief)
- What the new hire will be working on initially
- Any specific areas where the new hire might need extra support (e.g., "They're new to our tech stack" or "They're coming from a much larger company")
- The buddy meeting cadence expectation
- Permission to reduce their own workload slightly during Week 1 to make time
